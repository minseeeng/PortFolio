## 1. 실시간 대전 서버: 측정으로 찾은 문제들

서버가 20ms 프레임마다 이동과 공격을 판정하고 브로드캐스트하는 select 기반 서버입니다.
"접속하면 된다"에서 멈추지 않고, 더미 클라이언트로 N명을 접속시켜 직접 부하를 걸었습니다.

| 증상 | 원인 | 해결 | 확인 |
|---|---|---|---|
| 접속자 0명인데 CPU 한 코어가 100% | select 타임아웃 0, 루프가 쉬지 않음 | 타임아웃 1ms | 5초 중 CPU 사용 시간 **4.84초 → 0.17초** |
| 39번째 접속자부터 패킷 깨짐 | 송신 버퍼 500바이트, 패킷을 잘라 넣음 | 버퍼 10,000바이트, 못 넣으면 세션 종료 | 더미 클라이언트 도달률 |
| 64번째 접속자 무반응 | `FD_SET` 64칸 초과 소켓을 조용히 무시 | 정원 초과 시 명시적으로 접속 거절 | 더미 클라이언트 |
| 접속 종료 시 크래시 | 순회 중 삭제로 반복자 무효화 | 지연 삭제 | 크래시 재발 없음 |
| 좌표 검증이 반대로 동작 | 검증 조건이 반대 | 수정 후 오차 밖이면 거부 | — |

- **링버퍼**는 서버에 올리기 전에 `std::string`을 정답 모델로 두고, Enqueue / Dequeue / Peek를 회당 1만~5만 번 무작위로 실행해 매 연산 결과를 대조했습니다.
- 자세한 내용 → [game-server-portfolio](https://github.com/minseeeng/game-server-portfolio)

## 2. 온라인 장기: 서버와 클라이언트를 혼자 끝까지

기획 결정부터 패킷 설계, 서버, 클라이언트 UI까지 혼자 만드는 2인 대전 장기입니다.
"방장이 나가면 방을 넘길까?" 같은 질문은 코드가 아니라 기획 결정이었고, 이 답을 정해야 코드가 나아갔습니다.

- **구조화**: 5단계(닉네임 · 로비 · 방 · 장기 · 예외 처리) → **37개 태스크**. 각 태스크에 네트워크(N) / UI(U) 표시
- **핵심 경로**: 방 입장 → 나가기 → 게임 시작 → 장기 규칙 → 네트워크 대전 → 끊김 처리. 일정이 밀리면 자를 순서를 미리 정해 둠
- **현재**: 닉네임 · 로비(유저 목록, 채팅) · 방 만들기 완료 / 방 입장 · 장기 규칙 진행 중
- 자세한 내용 → [board-game/](board-game/)

## 3. AI 워크플로: 맡기는 기준과 검증

| 일의 종류 | AI의 역할 | 사례 |
|---|---|---|
| 배우는 코드 | 리뷰만. 완성 코드는 받지 않음 | 설계 질문에 내 답을 먼저 쓰고 AI의 시각과 비교 |
| 결과물이 목적인 일 | 맡기고, 기준과 대조해 검증 | 990줄 단일 파일 서버를 `Server` / `Session` / `App`으로 분리 → 원본과 동작 대조 |
| AI의 판단 | 그대로 믿지 않음 | 크래시 원인을 AI는 락 문제로 보고 뮤텍스를 제안 → 실제 원인은 순회 중 삭제 |

- Obsidian 노트 폴더에서 Claude Code를 실행해 노트를 AI의 바깥 기억으로 씁니다. 반복 작업은 [스킬](ai-workflow/briefing-skill/SKILL.md)로 만듭니다.
