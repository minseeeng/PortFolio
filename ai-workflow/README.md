# AI 워크플로: 무엇을 맡기고, 무엇을 직접 하는가

> **배울 때는 코드를 받지 않고, 결과물을 다듬을 때는 맡긴다.**
> 맡긴 결과는 반드시 기준과 대조해 검증하고, AI의 판단은 내 경험과 측정으로 확인합니다.

---

## 1. 환경

| 도구 | 쓰임 |
|---|---|
| **Claude Code** | Obsidian 노트 폴더에서 실행. 코드 리뷰, 리팩터링, 계획 점검, 반복 작업 자동화 |
| **Obsidian** | AI의 바깥 기억. 계획, 공부일지, 설계 기록, 막혔던 지점을 쌓음 |
| **CLAUDE.md · 메모리** | 규칙만 짧게. 11개까지 늘었던 지침을 AI가 놓치기 시작해 8개로 정리 |
| **커스텀 스킬** | 반복 작업을 명령 하나로 ([브리핑 스킬](briefing-skill/SKILL.md)) |

노트는 4개 폴더로 나눕니다: 진행 중(기한 있는 일) · 계속 관리 · 참고 자료 · 끝난 것.
새 세션도 노트를 읽고 바로 이어 가므로, 같은 설명을 반복하지 않습니다.

---

## 2. 일의 목적에 따라 역할을 나눈다

| | 배우는 코드 | 결과물이 목적인 일 |
|---|---|---|
| 코드는 누가 | **내가** | AI가 (나는 검증·보충) |
| AI의 역할 | 개념 확인 → 내가 백지 구현 → AI 리뷰 | 구현, 리팩터링, 테스트 도구 |
| 남는 것 | 면접에서 드러나는 내공 | 빠른 결과물 |
| 완료 기준 | 백지에서 내 말로 설명할 수 있는가 | 원본·기준과 대조해 동작이 같은가 |

### 한 세션의 흐름

1. **내가 먼저** 목표와 구조를 말한다
2. AI가 이해한 내용을 확인한다 (어긋나면 여기서 바로잡음)
3. 작업
4. **판단 기록**: 무엇을 맡겼고, 무엇을 고쳤고, 왜 그랬는지 적는다

### 리뷰 받는 규칙

- 버그 **위치**를 바로 알려 달라고 하지 않고, **범위와 검산 항목**(부등호, return, 읽기/쓰기 짝, 지운 이름)만 받는다
- 내 답을 먼저 쓰고, 한 번 답했거나 막히면 그때 AI의 판단을 받는다
- AI는 **내가 이미 짚은 곳 밖의 판단을 1개 이상** 내야 한다. 이미 아는 것만 확인해 주면 리뷰의 가치가 없기 때문

## 3. 사례

### ① 맡기고 검증하기: 990줄 서버 분리

실시간 대전 서버(TCPFighter)가 한 파일 990줄이었습니다. 서버 동작은 이미 직접 구현하고 이해한 상태라, 구조를 나누는 "다듬기"는 AI에게 맡겼습니다.
→ `Server` / `Session` / `App`으로 분리한 뒤, **원본과 동작을 대조**해 같은지 확인했습니다.
([game-server-portfolio](https://github.com/minseeeng/game-server-portfolio))

### ② AI의 판단을 의심하기: 뮤텍스 제안

브로드캐스트 중 크래시가 났을 때 AI는 락 문제로 보고 **뮤텍스를 제안**했습니다.
하지만 예전에 select 서버에서 같은 증상을 겪어 본 덕분에, 실제 원인이 **순회 중 삭제(반복자 무효화)** 라는 것을 알아보고 직접 고쳤습니다.
→ AI가 그럴듯한 답을 낼수록, 그 답을 판단할 수 있는 도메인 지식이 필요하다는 것을 배웠습니다.

### ③ 기준이 생긴 계기: AI가 짠 커리큘럼을 그만둔 이유

처음에는 AI가 짜 준 6개월 커리큘럼으로 시작했습니다. 하지만 따라 하기만 해서는 공부가 된다는 느낌이 없었습니다.
그래서 그만두고 "배울 때는 받지 않는다"는 기준을 세웠습니다.

### ④ 설계를 코드 전에 시험하기

구현 전에 AI에게 **설계를 시험할 질문**을 받고, 내 답을 먼저 쓴 뒤 AI의 시각과 비교합니다.

> 질문: "로비에 OK 버튼을 하나 더 달면 무엇을 몇 개 더 만들어야 하나?"
> 내 답: 버튼 하나당 스프라이트 3개(프레임) + 위치 → 손대는 곳 6군데
> 비교해서 찾은 것: 같은 버튼 2개면 **같은 비트맵을 두 번 로드**함 → 스프라이트를 공유하는 `ResourceManager`로 구조 변경

### ⑤ AI 결과물도 검산하기

AI가 복구한 학습 노트의 문제 박스 58개를 그대로 쓰지 않고 실행해서 검산했고, **지문 누락 10건**을 찾았습니다.

### ⑥ 반복 작업을 스킬로: 브리핑 스킬

매일 "어디까지 했지?"를 다시 찾는 시간을 줄이려고 직접 만든 Claude Code 스킬입니다.
최근 2일간 수정된 노트를 읽고 → 진행 중인 것, 완료한 것, 다음 할 일, 막힌 부분을 정리해 → 브리핑 노트를 만들고 Obsidian에서 엽니다.
→ [briefing-skill/SKILL.md](briefing-skill/SKILL.md)

## 4. 따라 하는 법

1. Obsidian 볼트 폴더에서 `claude` 실행
2. 볼트 루트에 `CLAUDE.md`를 두고 **규칙만** 5~8줄로 적기 (폴더 구조, 노트 작성 규칙, 배우는 코드는 완성 코드 금지)
3. 작업 전 목표와 구조를 먼저 말하고, AI의 이해를 확인한 뒤 시작
4. 끝나면 "맡긴 것 / 고친 것 / 이유"를 공부일지에 한 줄
5. 같은 지시를 세 번 반복했다면 스킬로 만들기 (`.claude/skills/<이름>/SKILL.md`)
